# Generated artifacts: what `env-cap` produces, and what it deliberately doesn't

This is the canonical place — for a human or an AI agent working in this
repository or a consuming project — to check before assuming `env-cap`
generates something it doesn't. Every artifact below is produced by
`generateEnvArtifacts()` (or the `env-cap` CLI, its thin wrapper); nothing
here is generated by a separate, independently-derived pipeline. Concretely:
`computeArtifacts` (the function both `generateEnvArtifacts` and
`checkArtifacts` share) runs one `assembleProject()` parse/link pass, then
builds all seven canonical fact models (ADR 0024) from that single result —
every artifact in this file is a projection of that same run's models, not a
second, independently-assembled source. `--evidence <path>` writes the
composed Evidence Model to disk directly, as JSON, for a project that wants
the canonical artifact itself rather than only its Markdown projections.

**Every artifact in this table is evidence that can _support_ a review
process — a security review, a privacy review, a platform audit — never a
compliance claim.** Static analysis of one repository cannot, by itself,
establish compliance with any external standard. Every rendered artifact
that carries this claim opens with the same disclaimer
(`evidenceDisclaimer()` in `generated-banner.ts`, byte-identical to
data-cap's own):

> Machine-generated engineering artifact assembled from statically-provable
> code facts and author-declared documentation. It can support a security,
> privacy, or compliance review. It does not itself establish compliance
> with any standard.

## Declared vs. proven vs. evidence

Every fact in every generated artifact is one of exactly three kinds, and a
rendering function may never blend them or imply one is another:

- **Declared** — metadata the author wrote via `documentEnv()`'s
  `VariableDocs`/`ContractDocs`: `description`, `owner`, `sensitivity`,
  `expiresAt`, `refreshInstructions`, `setupInstructions`, `required`,
  `deprecated`/`deprecatedReason`/`removeBy`, `renamedFrom`, `purpose`,
  `legalBasis`, `retention`, `dataResidency`, `auditRequired`, `metadata`.
  Presence is checked; correctness, adequacy, and enforcement are never
  claimed. A report may say a variable's retention policy is _"documented,"_
  never that it is _"sufficient"_ or _"enforced."_
- **Proven** — facts derived by AST analysis of the actual source: whether a
  declared variable is actually read anywhere in the scanned surface
  (`UNCONSUMED_OWNED_VARIABLE`), which files import/reference a given
  contract (Dependency Model), and every exclusive-group/compatibility
  conflict between contracts (`FindingCode`'s compatibility family). These
  are statically provable from the code that exists today, in this
  repository, at analysis time.
- **A third case, named explicitly because it's neither** —
  `VariableDocs.evidence.dynamicAccess` (ADR 0053-equivalent citation
  mechanism, mirroring data-cap's identical design) is declared, like every
  other governance field, but unlike every other one it's re-verified every
  run against a persisted content hash of the cited file
  (`MISSING_DYNAMIC_ACCESS_CITATION`/`STALE_DYNAMIC_ACCESS_CITATION`). A
  passing check establishes only that the citation is currently _supported
  by its own citation/integrity state_ — the cited file exists and hasn't
  visibly changed since the developer wrote it — never that the described
  access has been proven to happen there. No rendering of this field ever
  uses "verified" or "proven" language for this reason.

## Built in this release

| Artifact                                          | Generator                                      | What it answers                                                                                                                                                                                                                                                                                                              |
| ------------------------------------------------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Manifest** (`--location`)                       | `generateEnvManifest` (Contract Model)         | A single, deterministic `.ts` file re-exporting every _active_ contract — a projection of the Contract Model, not a second source of truth. `runtime/validate.ts` validates real `process.env` values against exactly this manifest.                                                                                         |
| **Documentation catalog** (`--docs`)              | `generateDocumentation`                        | Per-contract variables: `description` ("why"), `owner`/`sensitivity`/`purpose`/`legalBasis`/`retention`/`dataResidency` (labeled declared, not verified), plus a live "expiring soon or already expired" section sourced from the Lifecycle Model.                                                                           |
| **`.env.example`** (`--docs --env-example`)       | `generateDocumentation`                        | One line per active variable, generated from the same declared metadata `--docs` renders — never hand-maintained, never a second copy of the schema to drift from the real one.                                                                                                                                              |
| **Dependency & Ownership report** (`--ownership`) | `generateUsage` (Dependency + Ownership Model) | The owner → variables matrix, plus a real, in-repo, AST-proven consumer graph: which files actually read which variable — never guessed at. `UNCONSUMED_OWNED_VARIABLE`/`ABANDONED_CONTRACT` are warnings; `UNRESOLVED_CONSUMER`/`INDETERMINATE_OWNERSHIP` stay info, escalated only by `--strict-ownership`.                |
| **Evidence Model** (`--evidence`, ADR 0038)       | `generateEvidenceModel`                        | The composed `EvidenceModel` (ADR 0024's seventh model) as JSON, plus a paired `.fingerprint` sidecar — Contract/Dependency/Ownership/Finding/Lifecycle/Change models, whichever were computed this run. Always composed in-memory even without this flag; the flag only controls whether it's additionally written to disk. |
| **JSON report** (`--json`)                        | CLI (`src/cli/json.ts`)                        | The full result — every finding, every generator's output, and the composed Evidence Model — as one versioned envelope (`env-cap/schema`), for a CI step or another tool to consume without parsing human-readable text.                                                                                                     |
| **Drift check** (`--check`)                       | `checkArtifacts`                               | Recomputes every requested artifact and diffs it against disk — writes nothing, exits non-zero if anything is stale or missing. Its exit code reflects staleness only, independent of `--strict*` finding severity.                                                                                                          |
| **SARIF log**                                     | `buildSarifLog` (library export)               | A SARIF 2.1.0 adapter over the Finding Model, for a security-tooling pipeline that already ingests SARIF. Not CLI-wired — an ordinary consumer of the public Finding Model type, called directly by whichever project needs it (the same boundary Phase 4/5's own generator scripts sit behind).                             |

## Canonical fact models (ADR 0024)

Seven canonical, versioned, JSON-serializable models — the machine-readable
surface every rendered artifact above is a projection of, and what
`defineEvidenceProjection()` consumers (below) read instead of re-deriving
facts from raw source.

| Model            | Builder                 | What it answers                                                                                                                                                                                                                                                                     |
| ---------------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Contract Model   | `buildContractModel`    | Every discovered contract (active or not) and its variables — the schema shape itself, projected and sorted deterministically.                                                                                                                                                      |
| Dependency Model | `buildDependencyModel`  | Every proven consumer relationship, indexed by contract/variable and by consuming file — the fact the ownership report projects, computed once.                                                                                                                                     |
| Ownership Model  | `buildOwnershipModel`   | Every contract and variable's effective owner, plus first-class `unownedContracts`/`unownedVariables` arrays.                                                                                                                                                                       |
| Finding Model    | `buildFindingModel`     | Every rule violation and derived risk signal, unified behind one shape with a stable `code` and a structured `EvidenceReference` — the input the SARIF adapter and Evidence Model compose from.                                                                                     |
| Lifecycle Model  | `buildLifecycleModel`   | Every contract and variable's lifecycle data: expiry, deprecation, rename correlation.                                                                                                                                                                                              |
| Change Model     | `buildChangeModel`      | What changed since the last persisted evidence snapshot — the manifest diff, keyed for a "changes since last report" section.                                                                                                                                                       |
| Evidence Model   | `generateEvidenceModel` | The composition of the other six into one artifact — what every reference projection below reads. Two of the seven are separately published as JSON Schema (`env-cap/schema`, `env-cap/schema/contract-model`); the rest are TypeScript-typed only, not yet independently schema'd. |

A first wave of reference projections ships alongside the models themselves
— `configurationReference`, `ownershipSummary`, and `expiringSoonReport`
(all built through `defineEvidenceProjection()`), plus `buildSarifLog` (a
SARIF 2.1.0 adapter over Finding Model). Every one of these is an ordinary
consumer of the public model types above — none has a privileged internal
path a downstream tool couldn't also use. Phase 5's open-standard
alignment-evidence generator (see `specs/decisions/`, once written) is
architecturally no different: another `defineEvidenceProjection()` consumer,
not a bespoke script bypassing this model.
